Best Practices for die KonfigurationUm ein stabiles WebRTC-Streaming unter gVisor zu gewährleisten, sollten Sie folgende Anpassungen vornehmen:Option A: Network Passthrough aktivieren (Empfohlen for Performance)Wenn die Sicherheitsrichtlinien es erlauben, sollten Sie for den WebRTC-Container den Netzwerk-Passthrough-Modus aktivieren. Dadurch umgeht die Anwendung den gVisor-Netstack and greift direkt on den Host-Netzwerkstack zu. [1] (https://gvisor.dev/blog/2020/04/02/gvisor-networking-security/)Vorteil: Nahezu native Netzwerk-Performance and minimale Latenz for den Videostream.Nachteil: Verringert die Isolation des Netzwerk-Layers leicht.Konfiguration: Setzen Sie das Flag --network=host beim Start von runsc or konfigurieren Sie es in Ihrer /etc/docker/daemon.json for gVisor. [1] (https://gvisor.dev/docs/user_guide/networking/), [2] (https://gvisor.dev/blog/2020/04/02/gvisor-networking-security/)Option B: Optimierung at Nutzung des integrierten NetstacksMüssen Sie from Sicherheitsgründen die strikte Netzwerk-Isolation beibehalten, optimieren Sie den Netstack: [1] (https://gvisor.dev/docs/architecture_guide/networking/), [2] (https://gvisor.dev/docs/architecture_guide/networking/)BBR Congestion Control: Stellen Sie sicher, dass gVisor so konfiguriert ist, dass moderne TCP/UDP-Optimierungen greifen (gVisor unterstützt Protokolle wie BBR and RACK). [1] (https://gvisor.dev/blog/2020/04/02/gvisor-networking-security/)Port-Range einschränken: Konfigurieren Sie Ihren WebRTC-Server (z. B. die config.toml von LiveKit or janus.jcfg), um die genutzte UDP-Port-Range extrem einzugrenzen (z.
